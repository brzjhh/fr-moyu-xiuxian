## 1. 当前状态（交接基线）

用户确认托盘修正后“好了”。阶段 A 已有可预览的 Windows 桌宠，但仍是本地技术原型，不是正式发布版。

已实现：原创 Q 版青岚修士与五种动作、洞府/桌宠切换、拖动、倍率、置顶、穿透、托盘隐藏恢复、本地偏好保存和屏外位置恢复。洞府固定440×660，桌宠230×270按倍率取整；往返切换前清除旧min/max约束。

没有实现：服务器、数据库、账号、真实修炼、离线收益、突破、背包、宗门、组队。Windows/Mac互通只是目标，尚未实现。Mac x64/arm64已有配置但未实测。无签名、公证或云部署。

上级需求文档中的“尚未创建代码”是立项历史状态，最新进度以本文件及测试记录为准。

## 2. 代码结构与接口

- src/electron/main.ts：窗口状态、菜单、托盘、单实例、有限IPC、偏好、恢复、smoke测试。
- src/electron/settings.ts：偏好校验及显示器工作区位置约束。
- src/electron/preload.ts：隔离桥接，不暴露任意文件/命令执行。
- src/electron/repair-tray.ps1：Windows原生托盘补注册兼容处理。
- src/renderer/App.tsx：洞府与桌宠UI、状态订阅、拖动事件。
- src/renderer/Character.tsx：原创SVG角色；styles.css：样式和动作。
- assets/tray.ico：原创托盘图标。
- scripts/copy-electron-assets.cjs：构建时复制原生辅助脚本。
- scripts/package.cjs：Windows目录打包及Mac构建入口。
- scripts/launch-preview.ps1：独立启动器，本地用户目录及原生补注册。
- scripts/probe-*.ps1、test-native-tray.ps1：Windows原生诊断，非游戏逻辑。
- tests/settings.test.cjs：设置与窗口位置单元测试。

桥接：getState、command、onState。命令包括mode、activity、top、through、scale、hide、menu和drag-*。state是桌面偏好与演示动作，不是未来服务器权威角色存档。业务服务必须另建协议。

## 3. 已知启动与托盘问题（必须保留）

### 3.1 启动限制

本机Windows10 19044默认Electron启动曾返回0x80000003。普通用户目录也出现过启动/子进程异常。诊断启动使用 --no-sandbox 和独立 local-preview-profile 后可预览。

--no-sandbox降低进程隔离，仅允许本地原型使用，不作为正式联网发布方案。不可承诺根因已解决；先定位环境/版本兼容问题，再恢复正常安全启动。

### 3.2 托盘修复过程与最终规则

早期仅用tray.emit验证，不能证明通知区显示。更换图标、移除GUID并未单独解决。

上游Electron35.7.5的notify_icon_host.h中next_icon_id初始1，基础编号2，因此第一个托盘uid是3。此前用2补注册是错误项，已经在修复脚本中清理。

独立PowerShell通过Shell_NotifyIcon将图标登记到Electron_NotifyIconHostWindow，uid=3，回调消息WM_APP+1（32769），沿用Electron处理点击/菜单。原生查询取得正确uid的坐标；PostMessage验证打开→close隐藏→回调恢复全部通过，随后用户确认好了。

这一处理依赖当前Electron实现，不是稳定跨版本接口；升级时必须核对，未来优先移除兼容处理。客户端子进程中Add-Type曾拒绝访问，预编译库加载也拒绝；独立启动器可执行，所以当前使用外部启动器补注册。不要把实验生成的TrayRepair.dll当成必要源码或解决方案。

隐藏前注册验证失败时保留任务栏最小化入口；注册正常时隐藏到托盘。“桌宠 ↗”显示小修士，“−”和close隐藏，托盘点击/双击打开洞府。第二次启动可唤回已有进程。

### 3.3 当前可运行版与构建产物不完全同步

当前实际修复落在 release/尘途修仙_Windows原型_0.1.0/ 目录，其根部诊断CMD和launch-preview.ps1是当前入口。

根项目旧诊断CMD、先前ZIP及可能残留的win-unpacked目录不应视为最新入口。生成新发布包时必须把最新版launch-preview.ps1、诊断CMD、assets/tray.ico和dist-electron/repair-tray.ps1一起包含。scripts/package.cjs仅生成程序目录，不自动装配所有根级诊断入口，需要显式复制并测试。

打包脚本的Mac stage files清单仍需检查assets是否包含，不能据配置宣称已可分发。

## 4. 开发与恢复步骤

使用Node22+和pnpm；当前实测Node24.21.0、pnpm11.7.0、Electron35.7.5，锁文件为版本依据。

```sh
pnpm install --frozen-lockfile
# 若Electron二进制下载被安装策略跳过：
node node_modules/electron/install.js
pnpm typecheck
pnpm build
pnpm test
pnpm start
```

普通start在当前环境未可靠通过；不要自动默认加no-sandbox。运行smoke时关闭正常实例，使用隔离用户目录；其结果不能替代Mac实机或通知区物理点击验收。

Windows打包：pnpm pack:win。本项目主进程只依赖Electron与Node内建，React已被Vite打包，Windows采用官方Electron目录+resources/app，不需全局Node运行。发布目录整体保留，不能只复制EXE。

本机使用DSH提供的Node/pnpm路径，命令环境不一定有全局npm；换机后使用自己的工具路径，不硬编码原电脑路径。

## 6. 应备份什么

### A. 必须：开发源码与需求

保留src/、assets/、scripts/、tests/、package.json、pnpm-lock.yaml、tsconfig*.json、vite.config.ts、index.html、.gitignore、根CMD与全部Markdown；同时保存上级修仙桌宠游戏需求文档_v1.0.md。未来若有.git/，也应备份或推送私有远端。

本轮生成的“尘途修仙_源码与开发文档备份.zip”只包含这些开发文件和需求，不包含运行依赖、发布程序或用户配置。

### B. 强烈建议：当前能运行的完整解压版

备份整个 release/尘途修仙_Windows原型_0.1.0/，包括resources、locales、DLL、EXE、最新诊断CMD与launch-preview.ps1。不要只保存Chentu.exe，不要以此前旧ZIP替代当前目录。

这份快照可省去重装依赖、重构建和重新装配兼容启动器。复制前在托盘菜单退出程序，避免正在写入的用户目录不一致。

### C. 按需：本地偏好

当前诊断入口使用上述解压目录下 local-preview-profile/，包含位置、倍率、动作、置顶等偏好。最重要文件为其中desktop-settings.json。保留整个profile有利于原样恢复，但缓存可重建；没有账号/角色游戏进度，因为还未接入服务器。

普通启动可能使用%APPDATA%下的Electron用户目录；不要猜测路径，使用代码app.getPath('userData')或实际运行日志确定。不要删除或覆盖原用户数据。

### D. 可选：测试证据

TEST_REPORT.md应必备；artifacts中的smoke-result.json、PNG截图、相关测试日志可保留用于排查。大体积Electron下载ZIP、实验DLL不必备份。

### E. 可重新生成，不必备份

node_modules/、dist/、dist-electron/以及临时打包stage一般可通过锁文件和源码重建。注意“可运行快照”里面的resources/app/dist与dist-electron必须保留，不能按源码排除规则删掉！

### F. 未来增加服务器后的备份

届时必须新增PostgreSQL备份、迁移、服务端代码、配置和恢复演练；密钥/证书单独加密保存，不进公开Git或普通源码ZIP。目前这些服务及数据尚不存在。

## 7. 备份验证与保存策略

至少两份不同位置：电脑本地一份、移动硬盘或受控云盘一份。源码每次关键修改备份，可运行目录每次验证通过备份，记录版本和测试结论。

源码ZIP解压到新目录，检查需求、src、assets、scripts、锁文件和文档存在，再测试构建。可运行快照解压后使用诊断入口验证窗口与托盘，禁止只看到压缩成功就认为可恢复。

换AI时提供需求、开发交接与备份说明、开发进度、TEST_REPORT以及源码；若要复现当前Windows问题，再附当前可运行快照和日志。
