本文件是恢复工程后续功能记录的唯一更新入口。一个功能只保留一条记录；修复同一功能时更新原记录及验证结果，不重复追加状态描述。`README.md` 只写使用方法，其他原包文档保留为历史快照。

状态只根据实际证据填写。构建通过不等于界面可用，浏览器预览通过不等于 Electron 原生窗口通过；未验证的平台或交互明确标为待验收。

## 2026-10-15：参考图角色造型

状态：**正面像素精灵在浏览器界面已验证；逐帧动作与 Windows 原生窗口待验收**。

- 参考：`character-reference.png`。角色改用从原图提取的透明正面 PNG，保留原图的发型、五官、蓝金道袍、腰饰和像素颜色；没有制作 3D 模型或万剑阵技能。
- 实现：`scripts/extract-reference-sprite.py` 从设定图提取 `src/renderer/assets/character-front.png`；`src/renderer/Character.jsx` 在现有 SVG 容器中显示该精灵，并保留待机、打坐、行走、炼丹和御剑状态入口及炼丹、御剑效果。`styles.css` 使用最近邻像素显示和整身位移动效。
- 验证：Vite 生产构建通过；设置规则测试 2/2 通过。浏览器洞府中五种状态可切换，炼丹和御剑道具可见；230×270 桌宠视口中发冠、鞋子及透明边缘没有裁切。当前版本截图见 `character-panel-pixel-verified.png`。
- 限制：目前只有正面站姿，打坐和行走尚无专用逐帧像素动画；侧面、背面及参考图中的大剑还未提取为独立游戏素材。Windows 原生窗口及托盘仍待复验，Mac 未测试。旧版 SVG 的验收截图 `character-panel-verified.png` 和 `character-pet-verified.png` 不代表当前精灵版本。

### 本轮错误及原因

- 初次自动抠图丢失了深色头发内部，因为头发与渐变背景的颜色接近。已在提取脚本中补充头发轮廓蒙版，并复查透明预览和游戏内画面。
- 本轮 Vite 开发服务器的依赖预处理读取 React 文件时遇到目录访问拒绝，生产构建正常；浏览器验收改用 `vite preview` 提供的生产构建。开发服务器的权限问题尚未定位。
- 早期 SVG 重绘后曾出现浏览器页面空白。原因是 JSX 由当前 Vite 配置转换为 `React.createElement`，组件没有导入 `React`；当时已修复。本轮像素精灵组件保留导入。
- 原生隔离测试未能完成。可观察到进程启动但无可验证窗口、托盘脚本返回失败；**根因尚未查明**，不能归因于角色 SVG 或声称已修复。
- 仓库展示曾保留旧版 `character-panel-verified.png` 和 `character-pet-verified.png`，容易让 GitHub 页面看起来仍是旧角色；这两张历史截图不代表当前代码。当前版本新增 `character-panel-pixel-verified.png`，用于和 `6793d5c` 像素精灵提交对应。

- 原 Windows 运行包没有 source map 或 TypeScript 文件，恢复工程只能重建行为与可编辑结构，不能还原原始局部变量名、类型和注释。原源码丢失的原因未知。
