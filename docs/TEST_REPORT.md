### 本机启动限制

`诊断启动_仅本地原型.cmd` 显式传递 `--no-sandbox`，仅用于预览本地页面；正常入口不禁用沙盒。该参数降低进程安全隔离，不适用于正式联网发布。需进一步定位机器/进程环境与 Chromium 沙盒初始化问题，正常启动及阶段 A 完整验收目前仍未完成。

### 构建工具限制

## 最小化丢失入口修复

用户反馈洞府“−”后找不到桌宠和托盘。检查发现该按钮原执行 hide，现改为收起成可见桌宠；close 也收起桌宠。显式隐藏在 Windows 改为保留任务栏的最小化，提供非托盘恢复入口；面板状态显示任务栏，桌宠模式不显示。原生诊断 smoke 已实际点击“−”并验证桌宠仍可见，以及 Windows 最小化和 restore 后状态恢复，通过（退出0）。托盘在用户环境不可见的具体原因尚未确认，不能声明已修复托盘显示。新版资源已部署到用户当前解压目录，启动仍使用独立本地目录的诊断脚本，沙盒问题未解决。

## 固定尺寸与托盘模式变更（最新行为）

用户要求像微信一样隐藏到托盘。最新实现取代上述任务栏兜底：洞府“桌宠 ↗”显示小修士，“−”与关闭隐藏到托盘；托盘单击/双击打开洞府并聚焦。洞府固定440×660，桌宠按倍率固定尺寸；切换前先解除旧min/max约束，避免约束更新顺序改变长度。自动测试五次往返的精确宽高、按钮隐藏、Tray对象与图像非空、模拟托盘click/double-click恢复、close隐藏，诊断模式退出0。模拟事件不等价于Windows通知区的人工点击验收，托盘图标实际可见性仍需用户确认。已更新当前解压目录资源，运行中的旧进程需退出后重新启动。

## Windows 通知区原生排查（后续结果）

- 桌宠与 Explorer 在同一会话；隐藏后进程仍存活。
- 更换PNG、移除GUID均不能使Electron图标取得有效坐标。
- 原生Shell_NotifyIcon测试可成功注册，说明通知区并非完全不可用。
- 根据Electron 35.7.5上游实现，当前首个图标使用宿主Electron_NotifyIconHostWindow、uid=3、回调WM_APP+1。独立PowerShell补注册后，Shell_NotifyIconGetRect查询到uid=3的坐标1633,1040,1657,1080（HRESULT=1亦属于非负返回，可能对应折叠项）。本轮终于取得实际系统注册证据，不仅是Tray对象存在。
- 客户端子进程内Add-Type遇到访问拒绝，预编译库加载也被拒；独立启动器路径可以执行。这些环境限制的根因未确定。
- 当前解压版诊断入口改用外部启动器创建进程并补注册；新增脚本与ICO已部署。
- hide在注册验证失败时保留任务栏最小化恢复，不能继续把用户完全隐藏。
- 用户当前运行的旧进程也已经通过独立脚本补注册。仍需用户实际看到并点击图标验收。
- repair-tray.ps1依赖首个托盘uid=3，是特定Electron版本的原型兼容处理，不应直接视作正式跨版本原生接口。后续应定位运行环境或升级验证，去掉此兼容处理。
- 默认沙盒启动仍未修复；Mac未测试。

## 原生回调往返验证

继续阅读完整上游notify_icon_host.h后发现next_icon_id初始为1，基数2，因此首个图标实际uid=3。前轮uid=2是错误兼容项，仅有坐标不代表可点击，现已清理。修正后查询实际宿主uid=3坐标1633,1040,1657,1080；通过PostMessage发送真实WM_APP+1/WM_LBUTTONDOWN验证Electron原生回调，opened=True、close hidden=True、restored=True。这不是tray.emit测试，已覆盖系统宿主到业务窗口链路，但仍不等于用户物理点击验收。修正脚本与启动器已部署到当前解压目录，当前运行实例已补注册并恢复窗口。

上游依据：https://cdn.jsdelivr.net/gh/electron/electron@v35.7.5/shell/browser/ui/win/notify_icon_host.h 与 notify_icon_host.cc。升级Electron时必须复核，不能硬编码跨版本承诺。
