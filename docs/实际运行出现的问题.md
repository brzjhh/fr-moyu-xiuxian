# 实际运行出现的问题

本文记录在 Windows 本机实际启动恢复工程时发现的问题、证据、原因和处理方式，供后续开发者或 AI 接手时优先参考。这里记录的是实际运行结果，不把推测写成已验证结论。

## 2026-10-16：本机启动与界面显示问题

### 1. PowerShell 找不到 pnpm

- 现象：在项目目录执行 `pnpm start:diagnostic` 时，PowerShell 报“无法将 pnpm 项识别为 cmdlet、函数、脚本文件或可运行程序”。
- 原因：本机当前 PowerShell 会话的 `PATH` 没有包含 Codex 提供的 Node/pnpm 运行时目录。
- 处理：临时加入以下目录后，`pnpm --version` 可用，并显示 `11.25.0`：

  ```powershell
  $env:Path = "C:\Users\Administrator\.cache\codex-runtimes\codex-primary-runtime\dependencies\node\bin;C:\Users\Administrator\.cache\codex-runtimes\codex-primary-runtime\dependencies\bin\fallback;$env:Path"
  ```

- 限制：这是当前 PowerShell 会话的临时环境变量，不代表系统永久安装了 Node.js 或 pnpm。

### 2. pnpm 可以运行，但 Electron 找不到 node

- 现象：直接调用 fallback `pnpm.cmd` 后，脚本报 `'node' 不是内部或外部命令`。
- 原因：只调用了 pnpm 的 fallback 路径，没有同时把 bundled Node.js 目录加入 `PATH`。
- 处理：按上面的方式同时加入 Node.js 与 pnpm fallback 目录后，构建和测试命令可以执行。

### 3. Electron 窗口只有标题，React 界面没有正常显示

- 现象：窗口标题为“尘途 · 青岚洞府”，托盘图标出现，但内容区没有完整洞府 UI，表现为透明窗口透出背景/只看到角色图。
- 原因：Electron 使用 `file://` 加载 `dist/index.html`，而 Vite 默认生成 `/assets/...` 绝对路径；在本地文件页面中，这些路径无法正确解析到项目的 `dist/assets` 目录，导致渲染脚本和样式没有按预期加载。
- 处理：将构建脚本改为：

  ```json
  "build": "vite build --base=./ && node scripts/copy-electron.cjs"
  ```

  这样构建后的 `dist/index.html` 使用 `./assets/...` 相对路径，适配 Electron 的 `file://` 加载方式。同时在主进程中加入 `did-fail-load`、`console-message`、`dom-ready` 和 `render-process-gone` 日志，方便后续定位类似问题。
- 验证：`pnpm build` 通过；`dist/index.html` 已确认使用 `./assets/...`；`pnpm test` 通过（2/2）。
- 当前限制：修复后的 Electron 原生窗口仍需要在用户本机重新启动并目视确认；不能仅凭构建成功宣称原生窗口验收完成。

### 4. DirectComposition 日志

- 现象：诊断启动时出现 `direct_composition_support.cc ... IDCompositionDevice4 failed` 和 `0x80004002`。
- 当前判断：这是 Chromium 图形能力探测日志，目前没有证据证明它是 React 界面空白的根因；不能直接把它当作致命错误。

## 后续排查顺序

1. 先确认 PowerShell 的 Node.js/pnpm `PATH`。
2. 运行 `pnpm build` 和 `pnpm test`。
3. 运行 `pnpm start:diagnostic`，确认窗口内容、托盘和切换交互。
4. 若仍为空白，保留终端中的 `Renderer load failed`、`Renderer console`、`Renderer gone` 日志，再继续排查，不要先进入阶段 B 功能开发。
